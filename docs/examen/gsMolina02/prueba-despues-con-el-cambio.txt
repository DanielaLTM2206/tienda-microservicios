QUE VERIFICA CADA CASO
----------------------
1. Token revocado          -> el guard lanza 401 en vez de dejar pasar
2. Mensaje distinguible    -> el 401 dice "revocado", no "invalido o expirado",
                              para que el cliente sepa que debe reautenticarse
                              y no que su token esta corrupto
3. Token no revocado       -> sigue pasando (no rompi el camino feliz)
4. Ruta @Public()          -> ni siquiera consulta Redis (login y health
                              siguen accesibles sin token)
5. Token sin claim jti     -> se rechaza en vez de asumir sesion viva
                              (tokens emitidos antes de este cambio)

Los casos 3 y 4 son la red de seguridad: prueban que el comportamiento
anterior del guard sigue intacto.

AISLAMIENTO DE LA PRUEBA
------------------------
Se espia el prototipo de AuthGuard('jwt') para simular que Passport ya
valido firma y expiracion. Asi la prueba mide UNICAMENTE el paso nuevo
(la consulta a la lista de revocados) y no depende de que haya un Redis
levantado ni de un token real firmado.
